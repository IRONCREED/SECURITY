# Учредительный профиль IRONCREED Security

Идентификатор: `ics-profile-001`.

Редакция: `0.3.0`.

Дата принятия: 2026-08-28.

Конституционное основание:
[`ics-constitution-adoption-001`](../CONSTITUTION.md), редакция `0.1.0`.

Настоящий профиль учреждает границы монорепозитория WordPress-плагинов
IRONCREED Security, порядок независимых пакетов, лицензионную карту, правила
приватности, выпуск в WordPress.org и первый продуктовый мандат.

## P01. Идентичность и область

Официальное имя — `IRONCREED Security`. Канонический репозиторий —
`https://github.com/IRONCREED/SECURITY`. Издательское направление связано с
IRONCREED, Zhovten Games и FOP Oksana Dubinetska.

Репозиторий охватывает только WordPress-плагины и необходимые им нормативные,
сборочные, проверочные и выпускные материалы. Темы WordPress, самостоятельные
веб-приложения, серверные агенты, SaaS, внутренние клиентские плагины EMBO и
общие исследования безопасности не входят сюда без изменения Профиля.

Каждый `/plugins/<slug>/` представляет один продукт с собственным slug,
версией, пакетом, readme, лицензией, данными, миграциями, тестами и жизненным
циклом. Общий порядок не превращает плагины в обязательный комплект.

## P02. Обязательный внешний порядок

Для распространяемых плагинов действуют право применимых юрисдикций, условия
GitHub, правила WordPress.org, лицензия WordPress, WordPress Coding Standards,
а также требования безопасности, приватности, интернационализации и
доступности экосистемы WordPress.

Правила каталога и стандарты кода проверяются по актуальным официальным
источникам перед каждой заявкой и выпуском. Локальная формулировка не
замораживает внешнюю редакцию и не отменяет новое обязательное требование.

Код и иные файлы внутри распространяемого каталога плагина сохраняют
GPL-совместимость. Собственным плагинам назначается `GPL-2.0-or-later`.

## P03. Источники намерения и полномочия

Первичным источником продуктового намерения и учредительным субъектом является
Sam Starling. FOP Oksana Dubinetska является организационным субъектом
репозитория и публикации. Разработчик реализует утверждённое задание. Команда
WordPress.org Plugins осуществляет внешнюю проверку и принимает самостоятельное
решение о каталожной публикации.

Отзывы, автоматические предложения, прототип и поведение хостинга становятся
основанием изменения через зафиксированное решение. Фактическая возможность
прочитать файл либо записать данные не учреждает соответствующего полномочия.

## P04. Канонический корпус

Один Git-коммит образует каноническое состояние. Его источники:

- `/CONSTITUTION.md` — акт о принятии универсального корпуса;
- `/governance/PROFILE.md` — настоящий Профиль;
- `/governance/acts.json` — реестр актов;
- `/governance/legislation/` — производное Законодательство;
- `/docs/` — межплагинные и выпускные контракты;
- `/plugins/<slug>/` — исходный субъект конкретного плагина;
- `/constitutional-guard/` — самостоятельный проект технического контроля IRON WARDEN;
- `/.licensing-policy/` и `/code-constitution/` — закреплённые источники;
- lockfiles и конфигурация инструментов — технические регуляторы.

ZIP, WordPress.org SVN, переводы и отчёты являются производными либо выпускными
представлениями. Они связываются с исходным коммитом и вручную не исправляются.

## P05. Первый продуктовый мандат

Первый плагин называется `IRONCREED Request Log`, имеет slug
`ironcreed-request-log`, Product ID `ironcreed/request-log` и тему `security`.
Он предоставляет уполномоченному администратору два ясно различаемых
источника HTTP-журнала: локальный `WordPress Runtime` и опциональный
`Hosting Ukraine API`. Каждая запись показывает свой источник и границу
наблюдения.

`WordPress Runtime` остаётся переносимым встроенным источником. Он наблюдает
только запросы, при обработке которых загрузился WordPress. `Hosting
Ukraine API` получает authoritative nginx access logs через официальный
метод `hosting/log/web/nginx` и показывает запросы, которые не дошли до
WordPress, если такие записи возвращает провайдер.

Оба источника выключены после установки. Подключение Hosting Ukraine и каждое
получение журнала требуют явного уполномоченного действия. Фоновая
синхронизация, live tail, произвольный file path и `LocalFileProvider` в 1.0
отсутствуют.

## P06. Архитектурный порядок

Плагин разделяет доменные правила, прикладные сценарии, WordPress-адаптеры,
хранение и административный интерфейс. Домен не зависит от superglobals, базы
данных или HTML. Адаптеры преобразуют внешние значения в проверенные типы и
реализуют прикладные порты.

Внешняя связь в 1.0 ограничена документированным Hosting Ukraine API и
возникает только после opt-in. Запросы используют WordPress HTTP API, HTTPS,
фиксированный endpoint и ограничения времени и объёма. Telemetry endpoint,
удалённый код, внешние assets и собственный updater отсутствуют.

## P07. Данные, приватность и срок хранения

Оба источника выключены после установки. Включение локального observer и
подключение API являются раздельными явными действиями администратора.
До действия интерфейс описывает поля, источник, границу, цель, срок,
доступ и удаление.

`WordPress Runtime` сохраняет время UTC, метод, очищенный path и query,
статус, длительность, вид маршрута и источник. Он не сохраняет IP,
User-Agent и Referer. `Hosting Ukraine API` может получать время, IP,
метод, URI, статус, размер ответа, User-Agent и Referer. Эти значения,
а также идентификаторы в URI, рассматриваются как потенциальные персональные
данные на всём жизненном цикле.

Тела, cookies, authorization headers, пароли, nonce, API tokens, секреты и
значения чувствительных query не попадают в event storage, вывод, errors,
диагностику либо фикстуры. Query redaction применяется до сохранения.
Учётные данные провайдера хранятся отдельно от журнала, не autoload, не
отображаются повторно и удаляются при disconnect и uninstall.

Срок по умолчанию — 24 часа, hard cap — 10 000 записей. Настраиваемый срок не
превышает 30 дней, cap — 100 000. Cleanup выполняется периодически и при
достижении границы. Интерфейс предоставляет немедленное удаление. Uninstall
удаляет таблицы, параметры, capabilities и задачи.

## P08. Полномочия и управление

Просмотр требует `view_ironcreed_request_log`. Управление записью, connection,
ручным API fetch, сроком и удалением требует `manage_ironcreed_request_log`.
Capabilities назначаются
администраторам при активации и корректно обрабатываются в Multisite. Каждая
страница и endpoint повторно проверяет полномочие; изменение проверяет nonce.

Публичный REST endpoint, front-end вывод, email-рассылка и автоматический
экспорт не учреждаются. CSV-экспорт не входит в 1.0.

## P09. Межплагинная навигация

Плагины участвуют в `IRONCREED Suite Protocol v1`. Один активный плагин темы
`security` размещается в `Tools`. Два и более плагина одного vendor, theme и
major-протокола образуют `IRONCREED — Security`. Другая тема формирует
собственную группу либо остаётся самостоятельной.

Протокол не создаёт обязательной зависимости, общего storage, updater,
autoload либо полномочия одного плагина над другим.

## P10. Идентичность экземпляра

Product ID является неизменным. Activation guard отклоняет вторую активную
копию того же Product ID, даже если каталог переименован. Bootstrap guard
предотвращает fatal error и показывает точный конфликт. Плагин не
деактивирует другую копию автоматически и не выбирает победителя по версии.

## P11. Качество и доказательства

Требования связываются с автоматической проверкой либо конкретным review.
Обязательны WordPress Coding Standards, PHPCompatibilityWP, unit/integration и
negative-security tests, Plugin Check, проверка ZIP и ручной smoke test.

IRON WARDEN является техническим регулятором выпуска с единственной
способностью отказать кандидатной сборке. Его полный цикл объединяет integrity,
prebuild и postbuild, current tests, защищённый SHA-256 исторический корпус и
стабильный testing interface. WARDEN исполняет действующие нормы, не изменяет
их, не выдаёт исключения и не заменяет человеческий review.

Версия 1.0 ориентируется на PHP 8.0+. Минимальная WordPress устанавливается
реализацией после проверки реально используемых Core APIs.

## P12. Выпуск и WordPress.org

Первый выпуск является репутационным: полнота проверки, понятность интерфейса,
приватность и качество взаимодействия с Plugins Team имеют приоритет над
скоростью и количеством функций. Репозиторий становится публичным до подачи.

GitHub хранит разработку. WordPress.org SVN после одобрения используется как
release repository. Один выпуск создаётся одним проверенным пакетом с
совпадающими версиями. Частые микрокоммиты в SVN запрещены.

## P13. Защищённые положения

Без поправки к Профилю запрещено:

- называть WordPress-журнал полным server access log;
- включать журналирование, telemetry или внешнюю передачу по умолчанию;
- сохранять request body, cookies, authorization headers или секреты;
- выполнять API-запрос до opt-in или вне фиксированного Hosting Ukraine endpoint;
- сохранять или выводить API token как часть журнала, URL, error либо диагностики;
- давать одному IRONCREED-плагину скрытое управление другим;
- поставлять GPL-несовместимый код в пакете WordPress.org;
- обходить ограничения файловой системы или правила платформы;
- считать автоматическую проверку заменой ручного security/privacy review.

## P14. Изменение и восстановление

Изменение Product ID, схемы, default, capability, границы наблюдения, внешней
передачи, минимальной PHP, структуры меню, лицензии либо release channel
обновляет Профиль или Законодательство вместе с кодом и миграцией.

Security fix может получить ускоренный выпуск после фиксации основания,
масштаба, совместимости и rollback. Срочность не разрешает скрыть изменение
данных либо нарушить процедуру WordPress.org.
